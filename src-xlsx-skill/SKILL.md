# 公示 / 名单附件 PII 泄露审计

> 适用目标：高校、事业单位、医院、国企等把「名单类台账」以静态页面 + 附件形式长期挂在公网的站点。
> 漏洞本质：**数据脱敏只做了"看得见的那一层"**，容器的其它角落还留着源表。

## 0. 授权边界（别跳过）

只做**被动信息收集 + 匿名 GET**：搜索引擎已收录的页面、页面公开挂出的附件。
- 搜索 ≠ 授权测试。对真实目标只做只读访问，不爆破、不枚举、不写目标。
- 下载到的 PII 一律**脱敏存放**（脚本默认脱敏输出），不写进公开渠道、不发群、不进公开仓库。
- 拿不准范围先确认，报告里写清"匿名未授权访问"这一事实即可，不做二次利用。

---

## 1. 铁律：AI 最常漏掉的 4 件事

1. **看到名单页 ≠ 验证完成。** 页面上每个附件都必须下载 + 解包。
2. **附件正文列脱敏 ≠ 附件已脱敏。** xlsx 本质是 zip，必须解包看 `xl/externalLinks/`。
3. **第一眼干净 ≠ 真干净。** 还要看隐藏工作表、批注、自定义属性、文档属性、修订记录。
4. **判定"无泄露"之前必须过下面的门禁。**

### 自查门禁（6 问，答不上来就不许下结论）

| # | 问题 | 不过关的典型后果 |
|---|---|---|
| 1 | 页面里的附件**列全**了吗？（`href` + 正文纯文本 + JS 变量里的路径） | 一个页面常挂 3~5 个附件，只扫第一个 |
| 2 | 附件解包后 `xl/externalLinks/externalLink*.xml` 读了吗？`_rels` 里的外部目标路径看了吗？ | **漏掉本文档最重要的一条** |
| 3 | `xl/workbook.xml` 有没有 `state="hidden"` / `"veryHidden"` 的表？ | 公示只给 Sheet1，隐藏页是全量 |
| 4 | `xl/comments*.xml`、`xl/threadedComments/`、`docProps/core.xml`、`docProps/custom.xml` 扫了吗？ | 漏作者、漏批注里的备注 |
| 5 | 老格式 `.xls/.doc/.wps/.et`、`.docx` 的 `w:ins`/`w:del` 覆盖了吗？ | 被"删除"的身份证号仍在 XML 里 |
| 6 | 数字口径写清了吗？（列语义 vs 全文、掩码是否排除、出生年份区间） | 报告数字被复核推翻 |

## 2. 漏洞原理：Excel「外部链接缓存」

**为什么会出现**：经办人手里是一份带外部数据源的台账（`数据 → 查询与连接 / 外部链接`，或引用了另一个工作簿）。公示时他只删掉了不想公开的列、另存一份上传 —— 但 Excel 不会清理 `externalLinks` 缓存。

**缓存是什么**：读取源表时留下的**字符串快照**，与正文里还剩哪几列毫无关系。

**结构**（`xl/externalLinks/externalLink1.xml`）：

```xml
<externalLink xmlns="http://schemas.openxmlformats.org/spreadsheetml/2006/main">
  <externalBook r:id="rId1">
    <sheetNames><sheetName val="Sheet1"/></sheetNames>
    <sheetDataSet><sheetData sheetId="0">
      <row r="1"><cell r="A1" t="str"><v>毕业生姓名</v></cell> …</row>
      <row r="812"><cell r="D812" t="str"><v>4xxxxxxxxxxxxxxx7</v></cell> …</row>
```

**解析**：`zipfile` 打开 → 读该 entry → 按 `<row>` / `<cell r="D812">` 取值。

**顺手能捡到的附加证据（写报告很值钱）**：
- `xl/externalLinks/_rels/externalLink1.xml.rels` 里的 `Target="file:///..."` → **源台账的文件名/磁盘路径**。真实案例里直接暴露了内部台账名`（公示总表1557人)附件2：…汇总表.xlsx`。
- `docProps/core.xml` 的 `dc:creator` / `cp:lastModifiedBy` → 制表机器名、内设机构名（真实案例：`Lenovo` / `信息化管理中心`）。

**为什么必须报高危**：一次匿名 GET 就能拿到上千人的身份证 + 银行账号 + 住址，且已被搜索引擎收录、长期在线。

## 4. 一键扫描：`scripts/att_pii_scan.py`

零第三方依赖（仅标准库）；环境里若装了 `xlrd` / `pypdf`，会额外解析 `.xls` / `.pdf`。
**默认全程脱敏输出**（`1101**********002X`、`6212***********5371` 这种），要看原文才加 `--show-full`。

```bash
PY="python3"                                    # 3.9+ 即可；Windows 下用 python
S="src-xlsx-skill/scripts/att_pii_scan.py"

# 1) 首选用法：丢一个公示页进去，自动列出并逐个扫描页面里的所有附件
"$PY" -X utf8 "$S" "https://xxx.edu.cn/html/183/2026-05-22/content-14798.shtml"

# 2) 直接扫附件（URL 或本地文件都行，可一次传多个）
"$PY" -X utf8 "$S" "https://xxx.edu.cn/attachment/sites/item/2026_05/22_18/xxx.xlsx" --json out.json

# 3) 批量：每行一个 URL，只看命中的
"$PY" -X utf8 "$S" --input urls.txt --only-hit

# 4) 取证（打印原文样例 + 把原始附件落到 evidence/，慎用）
"$PY" -X utf8 "$S" "<URL>" --show-full --save ./evidence

# 常用开关
--born-max 2012   # 高校学生场景收窄出生年份（默认到当前年份）
--no-expand       # 不自动展开页面附件，只列清单
--timeout 60      # 站点慢时加长
```

输出要点（这是写报告的直接素材）：

```
🔴 确认泄露：身份证号列 1608 行过校验（列语义口径；全文口径去重 1608 个，报告用前者）
  HTTP=200  311334 bytes  type=application/…(zip)  zip条目=21
  ⚠ 外部数据源落盘路径(暴露内部路径/用户名): （公示总表1557人)附件2：…汇总表.xlsx
  · 文档属性: cp:lastModifiedBy=信息化管理中心; dc:creator=Lenovo
  身份证号: 校验通过=1608 / 18位形态=1614   手机号=1602   银行卡: Luhn通过=1543 / 16-19位形态=1557
  ★ 未脱敏数据载体（重点证据）:
      - xl/externalLinks/externalLink1.xml  id=1608 phone=1602 bank=1543 addr=1399
  ── 列语义核验（报告口径以此为准）──
     D 列「身份证号码」: 校验通过的身份证号 = 1608
     · H 列「毕业生开户银行账号」有 6 个 18 位数字（未过校验位），已排除在身份证统计外
```

## 5. 判定口径（防误报，报告数字以此为准）

**身份证号（三条件同时成立才算）**
1. GB11643 校验位：`W=[7,9,10,5,8,4,2,1,6,3,7,9,10,5,8,4,2]`，`CK="10X98765432"`
2. 前 2 位行政区码合法（11–15/21–23/31–37/41–46/50–54/61–65/71/81/82）
3. 出生年份在合理区间（默认 1900–当前年；高校学生建议 `--born-max 2012`）

**口径纪律（踩过的真坑，务必照做）**
- **优先用列语义口径**：表头含「身份证/证件号」的那一列的行数 = 报告数字；全文正则口径只作交叉验证。
- 反例：某表 **H 列「开户银行账号」里有 6 个 18 位数字**，形状像身份证 —— 靠列语义 + 校验位双重过滤才不会污染数字。反过来讲，**银行账号有约 1/11 概率偶然通过校验位**，所以"只靠校验位"是不够的。
- **XML 实体坑**：单元格值可能写成 `<v>469022200507170323&#10;</v>`（尾部换行实体）。解析前必须 `html.unescape()`，否则 `fullmatch` 判为不合格 → 少计 1 条。真实案例：看起来是 1607，真值 **1608**。这类差 1、差 2 的数字在 SRC 复核时很致命。
- **掩码不算泄露**：`4521242003****2127`、`139****2222` 这类单独计数并写明"已脱敏"，不与完整号混计。
- **银行卡给两级**：16–19 位形态（宽口径，容易混进学号/流水号）与 Luhn 通过（严口径），报告写清用哪级。
- **住址是启发式**，有噪声（会把「中国银行海南省陵水文教路」这种行名当地址），报告前人工过一遍。
- **数量少也得报**：20 个完整身份证号同样按高危写（真实案例）。

## 6. 最高产的 dork 家族

引擎现实：**360（`www.so.com`）是国内 edu 站唯一稳定的 dork 引擎**（`site:` 生效、结果带真实 URL）；且**不支持**子域级 `site:` 和 `filetype:`。

```
site:{根域} 补贴 (公示 OR 名单) 表
site:{根域} (助学金 OR 奖学金 OR 资助) 名单
site:{根域} (花名册 OR 汇总表 OR 登记表 OR 发放表)
site:{根域} 拟录取 公示
site:{根域} (求职补贴 OR 就业补贴 OR 困难补助)
site:{根域} ("身份证" OR "身份证号") 名单
```

补充：
- `site:根域` 天然覆盖子域（360 不支持 `site:sub.domain`）。
- 申请类文档的附件路径常有规律：`/attachment/sites/item/YYYY_MM/DD_HH/<hash>.<ext>`。**顺手 `curl -I` 一下该目录**：若目录可列（directory listing）本身就是另一条高危；不可列就停手，**不要枚举**。

## 8. 本机环境坑

- Windows 下建议用 **Git Bash** 执行；部分沙箱环境 PowerShell 不可用（ConPTY 限制），改用 Bash + 普通 Python 3。
- 长任务别在前台跑（会超时被强杀）→ 用后台运行 + 结果落文件。
- 抓 edu 站常遇自签证书 / 老旧 TLS：脚本已内置免证书校验 + `Connection: close`。
- 火绒 HIPS 会让 cmd/powershell 拉起的子进程多花约 1 秒 —— 与目标快慢无关，别误判。

## 9. 修复建议话术（可直接抄进报告）

1. 立即下线含源数据缓存的附件，替换为**新另存的脱敏文件**：`数据 → 查询与连接` 里删除全部外部链接与缓存，删除隐藏工作表，清理"文件 → 信息 → 检查文档"里的自定义属性/批注/修订记录。
2. 公示材料只保留**姓名 + 学号后四位**（或更少），身份证号、银行账号、手机号、家庭住址一律不出现。
3. 对站点 `attachment` 目录做一次全量排查，清理历史同类附件（这类文件往往还有多份）。
4. 建立发布前检查：公示附件统一由信息中心用脱敏模板生成，禁止用原始台账直接另存上传。
5. 已泄露数据不可撤回 → 建议对受影响人群做风险提示，并评估是否需要上报。

## 11. 负结果的分级（写报告前必读）

"没找到"有两种，混为一谈就是误报的反面——**把没查过的地方说成查过了**。

| 级别 | 条件 | 报告措辞 |
|---|---|---|
| **强负结果** | 对**现行站点**做全量审计：页面 + 全部附件 + 两种解析路径（zip 型 与 OLE 逐单元格） | 可写"未发现" |
| **弱负结果** | 结论依赖**第三方归档源**，且该源对目标存在系统性零覆盖 | 只能写"源侧无数据"，**不得写"已排除"** |

**判据：先证明覆盖度，再决定负结果强度。** 查归档源时先问：该源归档了目标多少 URL？有没有文档类附件（`urlkey:.*\.(xlsx|xls|doc|docx|pdf)$`）？若答案是"0 行"，那这个源根本没看过目标，它的"没有"毫无证据力。

> 实测教训：某 edu 站经 archive.org 核查为 0 命中，看似干净；但深查发现 archive.org 对该站公示栏目（`/xsc/`、`/rsc/`、`/attachment/`、`/upload/`）**全部 0 行归档**、文档附件全域名 0 行——而 360 dork 的历史命中证明那些页面确实存在过。故该结论只能是弱负结果。

**多源不等于独立源。** 宣称"多源交叉验证"前，必须先验证每个源**真的抓到了内容**（取一条实际记录看 HTTP 状态）。实测：CommonCrawl 与 archive.org 对同一目标同时零覆盖，根因是目标站 WAF 拒绝归档爬虫——用 WARC 取证坐实（Range 取 CC 的 robots 记录，得到的是 403 WAF 拦截页，署名"统一资源发布与管理系统"、原因"非法的 UserAgent"）。此时"多源"只是同一盲区被数了一遍。

## 12. 归档源当资产发现工具（高价值副产品）

`web.archive.org` 的 CDX 索引不止能查历史内容——**它能暴露当前 CT 日志与搜索引擎都覆盖不到的历史资产**（已下线/已删除的子域与路径）。

```
http://web.archive.org/cdx/search/cdx?url=<域名>&matchType=domain&output=json&collapse=urlkey&limit=5000
```

拿到后**按 host 聚类**，再按路径关键词筛选。实测：对某目标做 CDX domain 查询并按主机聚类，发现 3 个现行资产清单中完全没有、且当前 DNS 仍存活的子域（其中一个归档路径含"身份证读卡登录"的心理测评系统，正是最可能存身份证号的目标类型）。

其他可用源（含各自现实限制）：360（`m.so.com` 移动版可用，桌面版反爬；**快照功能已下线**）、百度（快照已下线）、Bing cache（多未索引 edu 域）、CommonCrawl（`index.commoncrawl.org/collinfo.json` 取索引列表，注意可能被 WAF 拦）、archive.today（需代理）。

## 13. 扫描器的三个静默失效点

负结果可信的前提是**扫描器真的读到了内容**。以下三处会导致"扫了但没读到"，且**不报错**：

1. **gzip 未透明解压**：raw 字节直扫会漏读 gzip 响应。实测某快照 raw 5911 字节，解压后 26757 字符——直接扫原始字节等于没扫。
2. **OLE 老格式只做字节扫描**：`.xls/.doc` 是 OLE 复合文档，字符串会分片，正则扫原始字节会漏检。**必须用 xlrd/olefile 逐单元格解析**。
3. **XML 实体未 unescape**：单元格值可能是 `<v>469022200507170323&#10;</v>`，不 unescape 就 `fullmatch` 失败、少计 1 条。

**对策：先做正/负对照自检**——喂一个合成的合法身份证号（应 5/5 通过）+ 一个错校验位号（应被拒），确认校验器工作正常，再下负结论。

## 14. 未验证 ≠ 已排除（措辞纪律）

以下三种情况**都不能写成"无泄露"**：

- **目标整站维护中**：所有路径返回同一个维护页（实测：真实路径与随机路径返回**同一 md5**）→ 路径存在性不可判定，线索**不可验证**。
- **被 WAF/CAS 全覆盖**：任意路径都被重定向到统一认证 → 只是"看不到"，不是"没有"。
- **接口强制鉴权**：后端返回鉴权错误（如 TokenID 格式错误）→ 说明端点存在且拒绝无凭据访问，属"已排除未授权面"，与"无此功能"是两回事。

判据：**先建基线再判定**。请求 2~3 个确定不存在的随机路径，与目标路径逐字节比对（长度 + md5 + 状态码）。二者相同 → 该路径的存在性不可判定；二者不同 → 差异才是证据。

> 反面教训：曾把"某接口返回 500"当作"控制器名错误"，实际是**请求体必须非空密文**（传空串即 500），最小需加密 `{}`。状态码相同不代表原因相同。
