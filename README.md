# xls / xlsx 附件 PII 泄露审计工作流

> 面向「公示 / 名单 / 花名册 / 补贴 / 拟录取」类**公开附件**的个人敏感信息（PII）泄露审计工具链。
> 四个组件：浏览器端离线分析器、命令行扫描器、本地 `.xls` 深挖提取器、AI Agent 方法论包。

## ⚠⚠⚠授权与免责⚠⚠⚠

本工具面向**安全研究、SRC 漏洞提交、以及对自己资产的合规自查**。

- 只做**被动信息收集 + 匿名 GET**：搜索引擎已收录的页面、页面公开挂出的附件
- 不做爆破、不做目录枚举、不写目标 —— 搜索 ≠ 授权测试
- 下载到的 PII 一律脱敏存放，不进公开仓库、不发群、不做二次利用
- 报告里只保留必要取证量（2–3 条，前 6 后 4 脱敏），完整数据只留在本地证据目录

⛔使用前请确认你对目标拥有测试授权。因使用本工具产生的一切后果由使用者自行承担。

## 简要原理

**脱敏只做了"看得见的那一层"。**

单位把内部台账 Excel 另存为公示附件上传时，通常只删掉不想公开的列 —— 但 `.xlsx` 本质是 zip，
`xl/externalLinks/externalLink1.xml` 里留着读取源表时生成的**未脱敏快照**；
`.xls` 是 OLE2 复合文档，被删掉的内容仍躺在 BIFF8 的 SST 记录里。

结果就是：正文脱敏了，缓存里还有身份证号、手机号、银行账号、家庭住址等敏感信息

完整机制、容器结构、判定算法 → [`docs/PRINCIPLE.md`](docs/PRINCIPLE.md)

## 工具：

### 1. 浏览器版 —— `xls.html`

下载后用浏览器打开（双击即可，无需起服务、无需装任何东西），把 `.xls` / `.xlsx` 拖进去。

- 识别 **18 位**与 **15 位**身份证号，并统计**校验位通过率**
- **自动解包 xlsx 的 `xl/externalLinks/` 缓存**，作为独立「工作表」列出来（这是本工具的核心能力）
- 全字段原样展示：分页、表头自动识别、命中单元格高亮、真实 Excel 行号
- 文档属性（作者 / 最后修改人 / 生成程序）
- 导出 TSV、CSV、身份证号清单，计算文件 SHA-256



### 2. 命令行版 —— `att_pii_scan.py`

（脚本位于 `src-xlsx-skill/scripts/att_pii_scan.py`）

```bash
# 扫一个公示页面：自动列出并逐个扫描页面里的所有附件
python att_pii_scan.py "https://www.example.edu.cn/html/183/2026-05-22/content-14798.shtml"

# 直接扫附件（URL 或本地路径都行，可一次传多个）
python att_pii_scan.py ./公示附件.xlsx --json out.json

# 批量：每行一个 URL，只看命中的
python att_pii_scan.py --input urls.txt --only-hit

# 常用开关
--show-full         # 输出未脱敏样例（默认全部脱敏）
--save ./evidence   # 把原始附件落盘取证（含未脱敏数据，慎用）
--born-max 2012     # 高校学生场景收窄出生年份（默认到当前年份）
--no-expand         # 不自动展开页面附件，只列清单
--timeout 60        # 站点慢时加长
```



### 3. 本地 `.xls` 深挖 —— `xls.py`

面向**本地**老式 `.xls`（OLE2 / BIFF8）的全字段提取。**不做脱敏** —— 它的目的是把数据完整还原出来。

```bash
python xls.py 在籍学生.xls        # 单个文件
python xls.py ./附件目录          # 整个目录（递归，自动跳过自己的产物）
python xls.py                     # 不带参数 = 扫当前目录
```

对每个 `.xls`，在它旁边生成：

| 产物 | 内容 |
|---|---|
| `<同名>_数据.txt` | 完整表格，TSV（Tab 分隔），原样保留所有列 |
| `<同名>_数据.xlsx` | 同一份数据，一个来源表一个 sheet，表头带样式、首行冻结 |
| `<同名>_身份证号.txt` | 仅 18 位身份证号（用于计数取证） |
| `<同名>_身份证号_15位.txt` | 老式 15 位号（有才生成） |

**与 `att_pii_scan.py` 的分工**：后者是「审计」——脱敏输出、给判定结论；`xls.py` 是「还原」——
不脱敏、把数据完整捞出来。要证明泄露量、要拿原始数据复核时用它。

#### 为什么需要它：数据不一定在单元格里

- `.xls` 是 OLE2 复合文档，**不是 zip，不能 unzip**
- 某些 `.xls`（业务系统导出后经 WPS 转存）把**整份名册**塞在 BIFF 记录 **`0x005A`（MS-XLS 的 Crn 记录）**里，
  工作表里根本没有"身份证号"这一列
- 这类载荷 `xlrd` / `openpyxl` **一律看不见** —— 只按单元格导出就会**静默丢数据**，
  症状是"号码清单里有 215 个，导出的 xlsx 里却找不到身份证列"

所以它做了**三路取并集**，少一路就漏：

| 路径 | 捞到什么 |
|---|---|
| 裸字节扫描（ASCII + UTF-16LE 双路） | 文本型号码 |
| `xlrd` 逐单元格 | **数字型**号码（在 BIFF 里是 IEEE double，字节流里根本没有数字字符） |
| BIFF 记录级扫描（`0x005A`） | 藏在非单元格载体里的号码 |

跑完会打印**载体对照**：有多少号码不在任何单元格中、分布在哪些记录里。

## 判定口径（防误报，报告数字以此为准）

**身份证号** —— 三条同时成立才算「确认泄露」：

1. GB 11643-1999 校验位通过（`W=[7,9,10,5,8,4,2,1,6,3,7,9,10,5,8,4,2]`，`CK="10X98765432"`）
2. 前 2 位是合法行政区划码（11–15 / 21–23 / 31–37 / 41–46 / 50–54 / 61–65 / 71 / 81 / 82）
3. 出生年份在合理区间（默认 1900–当前年；高校场景建议 `--born-max 2012`）

**报告数字用「列语义口径」**：表头含「身份证 / 证件号」的那一列的行数，而不是全文正则去重数。

> 反例：某表「开户银行账号」列里有 6 个 18 位数字，形状和身份证一模一样；而随机 18 位数字有约 **1/11** 的概率偶然满足校验位方程 —— 只靠正则必然污染数字。

**掩码不算泄露**（`4521242003****2127`），单独计数、单独说明。

**银行卡给两级口径**：16–19 位形态（宽口径，容易混进学号 / 流水号）与 Luhn 通过（严口径），报告里写清用的是哪一级。

**住址是启发式**，有噪声（会把「中国银行海南省陵水文教路」这种行名当地址），报告前人工过一遍。

## 已知局限

- 身份证号在原文件里若是**数值格式**且超过 15 位，Excel 保存时**本身就已丢精度**（尾数变 0），任何工具都无法还原 —— 这是文件的原生缺陷，不是解析问题
- `.docx` / `.pptx` 的同类风险在方法论里有覆盖思路，但脚本与浏览器工具暂未实现
- 15 位老式身份证号只校验出生日期合法性（无校验位），存在理论误报
- `.xls` 的表格结构解析依赖 `xlrd`（可选增强）；未安装时 `att_pii_scan.py` 退化为多编码裸扫，只给**下限**。
  `xls.py` 自带 CFB 解析与 BIFF 记录级扫描，**没有 `xlrd` 也能捞到字节级与 `0x005A` 载体里的号码**，
  但同样拿不到单元格表格结构
